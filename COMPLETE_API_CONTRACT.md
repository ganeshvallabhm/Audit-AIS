# CompanyAudit — Complete REST API Specification & Contract
**Platform:** CompanyAudit — Enterprise Audit & Performance Analytics Platform  
**Base Path:** `/api`  
**Protocol:** HTTP/1.1 & HTTP/2  
**Authentication Scheme:** Bearer JWT + Refresh/CSRF Double-Submit Cookies  
**Document Purpose:** Complete Contract Baseline for Python-to-Java Parity Migration  

---

## 1. Global Protocol, Headers & Error Envelope

### 1.1 Standard Request Headers

| Header | Description | Required When |
| :--- | :--- | :--- |
| `Authorization` | `Bearer <access_token>` | All protected routes (short-lived HS256 JWT) |
| `X-CSRF-Token` | Value of `companyaudit_csrf` cookie | State-changing requests (`POST`, `PUT`, `PATCH`, `DELETE`) and `/api/auth/refresh` |
| `Content-Type` | `application/json` (or `multipart/form-data`) | Requests containing a request body |
| `X-Request-ID` | UUID tracing identifier | Optional; generated by server if omitted |

### 1.2 Standard Security Response Headers

All HTTP responses must return the following security headers:
- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: DENY`
- `Referrer-Policy: strict-origin-when-cross-origin`
- `Permissions-Policy: camera=(), microphone=(), geolocation=()`
- `X-Request-ID: <uuid>`

### 1.3 Error Envelope Format

All non-2xx responses conform to the FastAPI-compatible JSON schema:

```json
{
  "detail": "Descriptive human-readable error explanation",
  "error_ref": "8f9a2e4b7c1d"
}
```

Validation errors (`422 Unprocessable Entity`) format `detail` as a list of field violations:
```json
{
  "detail": [
    {
      "loc": ["body", "target_score"],
      "msg": "Score must be between 0 and 100",
      "type": "value_error"
    }
  ]
}
```

## 2. Authentication & User Management (`/api/auth`)

### 2.1 `POST /api/auth/login`
- **Description:** Authenticates user credentials using Argon2id, mints a short-lived access JWT, and writes secure refresh/CSRF cookies.
- **RBAC:** Public.
- **Rate Limit:** 40 requests/60s per IP; 8 failed attempts/60s per IP+email.
- **Request Body:**
  ```json
  {
    "email": "eleanor.vance@companyaudit.io",
    "password": "StrongPassword123!"
  }
  ```
- **Response (200 OK):**
  - **Headers / Cookies:**
    - `Set-Cookie: companyaudit_refresh=<jwt>; HttpOnly; SameSite=Lax; Path=/; Max-Age=604800; [Secure]`
    - `Set-Cookie: companyaudit_csrf=<token>; SameSite=Lax; Path=/; Max-Age=604800; [Secure]`
  - **Body (`TokenResponse`):**
    ```json
    {
      "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
      "token_type": "bearer",
      "expires_in": 1800,
      "user": {
        "id": "c1f7274b-5136-4c40-bbd9-95a94a2ee6f8",
        "company_id": "a1b2c3d4-e5f6-7a8b-9c0d-1e2f3a4b5c6d",
        "department_id": null,
        "department_name": null,
        "email": "eleanor.vance@companyaudit.io",
        "full_name": "Eleanor Vance",
        "initials": "EV",
        "job_title": "Chief Audit Officer",
        "role": "Admin",
        "certifications": ["CPA", "CIA", "CISA"],
        "is_active": true,
        "last_login_at": "2026-11-21T10:00:00Z"
      }
    }
    ```
- **Errors:** `401 Unauthorized` (Invalid credentials), `429 Too Many Requests`.

### 2.2 `POST /api/auth/register`
- **Description:** Provisions a new user account within the caller's tenant.
- **RBAC:** `Admin` only.
- **Request Body (`RegisterUserRequest`):**
  ```json
  {
    "email": "new.auditor@companyaudit.io",
    "password": "InitialPassword123!",
    "full_name": "Jane Doe",
    "job_title": "Senior IT Auditor",
    "role": "Auditor",
    "department_id": "b3e2a100-3485-408a-8be2-7f287950c4bb",
    "certifications": ["CISA"]
  }
  ```
- **Response:** `201 Created` (`UserSummary`).
- **Errors:** `400 Bad Request`, `403 Forbidden`, `409 Conflict` (Email already registered).

### 2.3 `GET /api/auth/me`
- **Description:** Returns the active authenticated user profile.
- **RBAC:** All authenticated roles (`Admin`, `Auditor`, `Department Head`, `Management`, `Viewer`).
- **Response:** `200 OK` (`UserSummary`).

### 2.4 `POST /api/auth/refresh`
- **Description:** Rotates refresh token, invalidating the previous session, and mints a new access JWT. Detects token reuse (theft) and revokes token family on violation.
- **RBAC:** Public (authenticated via `companyaudit_refresh` cookie + `X-CSRF-Token` header).
- **Rate Limit:** 40 requests/60s per IP.
- **Response:** `200 OK` (`TokenResponse` with rotated cookies).
- **Errors:** `401 Unauthorized` (Expired, invalid, or reused refresh token).

### 2.5 `POST /api/auth/logout`
- **Description:** Invalids all active refresh sessions for the user and increments `token_version`.
- **RBAC:** All authenticated roles + valid CSRF cookie.
- **Response:** `200 OK` (`MessageResponse: {"message": "Logged out successfully"}`).
- **Cookies:** Clears `companyaudit_refresh` and `companyaudit_csrf`.

### 2.6 `GET /api/auth/users`
- **Description:** Lists all users in the authenticated tenant.
- **RBAC:** All authenticated roles.
- **Response:** `200 OK` (`list[UserSummary]`).

### 2.7 `PUT /api/auth/users/{user_id}`
- **Description:** Updates user profile, role assignment, or active status. Deactivating increments `token_version`.
- **RBAC:** `Admin` only.
- **Request Body:** `UserUpdateRequest` (`full_name?`, `job_title?`, `role?`, `department_id?`, `is_active?`, `certifications?`).
- **Response:** `200 OK` (`UserSummary`).

### 2.8 `POST /api/auth/users/{user_id}/reset-password`
- **Description:** Admin-triggered credential reset. Re-hashes password with Argon2id, increments `token_version`, and revokes active sessions.
- **RBAC:** `Admin` only.
- **Request Body:** `{"new_password": "NewStrongPassword123!"}`.
- **Response:** `200 OK` (`MessageResponse`).

## 4. Audits, Scopes, Checklists & Control Responses (`/api`)

### 4.1 `GET /api/audits`
- **Description:** Paginated retrieval of audits filtered by domain, status, or search term.
- **RBAC:** All authenticated roles.
- **Query Parameters:** `domain?`, `status?`, `department_id?`, `search?`, `limit` (1..200, def 50), `offset`.
- **Response:** `200 OK` (`PaginatedResponse[AuditOut]`).

### 4.2 `POST /api/audits`
- **Description:** Initiates an audit engagement and schedules its scopes.
- **RBAC:** `Admin` or `Auditor`.
- **Request Body (`AuditCreate`):**
  ```json
  {
    "code": "AUD-2025-101",
    "title": "Cloud Identity & Access Architecture",
    "domain": "Technology",
    "department_id": "b3e2a100-3485-408a-8be2-7f287950c4bb",
    "lead_auditor_id": "c1f7274b-5136-4c40-bbd9-95a94a2ee6f8",
    "framework": "SOC 2 Type II",
    "status": "Scheduled",
    "scheduled_start": "2026-12-01",
    "target_due_date": "2026-12-20",
    "summary": "Full AWS & Azure IAM role hygiene evaluation."
  }
  ```
- **Response:** `201 Created` (`AuditOut`).

### 4.3 `GET /api/audits/{audit_id}`
- **Description:** Detailed engagement view including scopes, allowed transitions, and stage progress.
- **RBAC:** All authenticated roles.
- **Response:** `200 OK` (`AuditOut`).

### 4.4 `PUT /api/audits/{audit_id}`
- **Description:** Updates audit details or transitions status.
- **RBAC:** `Admin` or `Auditor`.
- **Validation Rule:** Target status validated against `ALLOWED_AUDIT_TRANSITIONS`:
  - `Draft -> Scheduled`
  - `Scheduled -> In Progress | Draft`
  - `In Progress -> Review`
  - `Review -> Action Required | Verification`
  - `Action Required -> Verification | Review`
  - `Verification -> Closed | Review`
- **Response:** `200 OK` (`AuditOut`).
- **Errors:** `400 Bad Request` (Invalid transition).

### 4.5 `POST /api/audits/{audit_id}/scopes`
- **Description:** Adds an in-scope system, process, or regulatory clause.
- **RBAC:** `Admin` or `Auditor`.
- **Response:** `201 Created` (`AuditScopeOut`).
- **Errors:** `400 Bad Request` if audit status is `Closed`.

### 4.6 `PUT /api/audits/{audit_id}/scopes/{scope_id}`
- **Description:** Modifies an audit scope.
- **Response:** `200 OK` (`AuditScopeOut`).

### 4.7 `DELETE /api/audits/{audit_id}/scopes/{scope_id}`
- **Description:** Removes an audit scope.
- **Response:** `200 OK` (`MessageResponse`).

### 4.8 `GET /api/checklists`
- **Description:** Lists framework checklists and control items.
- **Query Parameters:** `domain?`, `audit_id?`.
- **Response:** `200 OK` (`list[ChecklistOut]`).

### 4.9 `POST /api/checklists`
- **Description:** Creates a new control framework checklist.
- **RBAC:** `Admin` or `Auditor`.
- **Response:** `201 Created` (`ChecklistOut`).

### 4.10 `POST /api/checklists/{checklist_id}/items`
- **Description:** Adds a control item with test procedure and weight.
- **RBAC:** `Admin` or `Auditor`.
- **Response:** `201 Created` (`ChecklistItemOut`).

### 4.11 `PUT /api/checklist-items/{item_id}`
- **Description:** Edits a control item test procedure or weight.
- **Response:** `200 OK` (`ChecklistItemOut`).

### 4.12 `GET /api/audits/{audit_id}/responses`
- **Description:** Lists all evaluated control responses for an audit.
- **Response:** `200 OK` (`list[AuditResponseOut]`).

### 4.13 `POST /api/audits/{audit_id}/responses`

## 5. Governance: Findings, CAPA & Risks (`/api`)

### 5.1 `GET /api/findings`
- **Description:** Paginated finding registry with severity, SLA, and owner filtering.
- **RBAC:** All authenticated roles.
- **Response:** `200 OK` (`PaginatedResponse[FindingOut]`).

### 5.2 `POST /api/findings`
- **Description:** Creates an audit non-conformance finding.
- **RBAC:** `Admin` or `Auditor`.
- **Request Body:** `FindingCreate` (`audit_id`, `department_id`, `title`, `root_cause`, `severity`, `target_sla_date`, etc.).
- **Response:** `201 Created` (`FindingOut`).

### 5.3 `PUT /api/findings/{finding_id}`
- **Description:** Modifies finding, submits management response, or executes sign-off.
- **RBAC:**
  - `Admin` & `Auditor`: Full edits.
  - `Management`: Approves sign-off (`sign_off=true`) or rejects with required `rejection_reason`.
  - `Department Head`: Updates `management_response` and sets status to `Verification Pending` (confined to own department).
- **Response:** `200 OK` (`FindingOut`).
- **Errors:** `403 Forbidden` if cross-department modification attempted.

### 5.4 `DELETE /api/findings/{finding_id}`
- **Description:** Deletes an open finding.
- **RBAC:** `Admin` or `Auditor`.
- **Validation:** Blocked if finding status is `Closed`.
- **Response:** `200 OK` (`MessageResponse`).

### 5.5 `POST /api/recommendations`
- **Description:** Adds remediation guidance linked to a finding or risk.
- **RBAC:** `Admin` or `Auditor`.
- **Response:** `201 Created` (`RecommendationOut`).

### 5.6 `POST /api/recommendations/{recommendation_id}/respond`
- **Description:** Submits management acceptance or counter-guidance.
- **RBAC:** `Admin`, `Management`, or `Department Head` (own dept).
- **Response:** `200 OK` (`RecommendationOut`).

### 5.7 `GET /api/actions`
- **Description:** Lists Corrective Action Plans (CAPA).
- **Response:** `200 OK` (`PaginatedResponse[CorrectiveActionOut]`).

### 5.8 `POST /api/actions`
- **Description:** Creates a corrective action task.
- **RBAC:** `Admin`, `Auditor`, or `Department Head` (own dept).
- **Response:** `201 Created` (`CorrectiveActionOut`).

### 5.9 `PUT /api/actions/{action_id}`
- **Description:** Updates progress %, submits for review, or marks verified.
- **RBAC:** Role-checked; only `Admin` or `Auditor` can mark status `Verified`.
- **Response:** `200 OK` (`CorrectiveActionOut`).

### 5.10 `DELETE /api/actions/{action_id}`
- **Description:** Deletes a corrective action.
- **RBAC:** `Admin` or `Auditor`. Blocked if status is `Verified`.
- **Response:** `200 OK` (`MessageResponse`).

### 5.11 `GET /api/risks`
- **Description:** Retrieves 5x5 threat risk matrix entries.
- **Response:** `200 OK` (`PaginatedResponse[RiskOut]`).

### 5.12 `POST /api/risks`
- **Description:** Creates an enterprise risk record with probability (`1..5`) and impact (`1..5`).
- **RBAC:** `Admin` or `Auditor`.
- **Response:** `201 Created` (`RiskOut`).

### 5.13 `PUT /api/risks/{risk_id}`
- **Description:** Updates mitigation strategy, residual scores, or review date.
- **RBAC:** `Admin`, `Auditor`, or `Management`.

### 5.14 `POST /api/risks/{risk_id}/escalate`

## 6. Evidence Vault (`/api/evidence`)

### 6.1 `GET /api/evidence`
- **Description:** Paginated inventory of audit evidence files.
- **Response:** `200 OK` (`PaginatedResponse[EvidenceOut]`).

### 6.2 `POST /api/evidence`
- **Description:** Multipart file upload. Enforces 25 MB cap, magic-byte inspection, and computes SHA-256 digest.
- **RBAC:** `Admin`, `Auditor`, or `Department Head` (own dept).
- **Rate Limit:** 25 uploads/60s per IP.
- **Form Data:**
  - `file`: Binary file.
  - `audit_id?`, `finding_id?`, `corrective_action_id?`, `checklist_item_id?`, `tag?`.
- **Response:** `201 Created` (`EvidenceOut`).
- **Errors:** `413 Payload Too Large` (>25 MB), `415 Unsupported Media Type` (executable or magic byte mismatch).

### 6.3 `GET /api/evidence/{evidence_id}/download`
- **Description:** Streams raw evidence bytes with on-the-fly disk SHA-256 verification.
- **RBAC:** All authenticated roles.
- **Headers Returned:**
  - `Content-Disposition: attachment; filename="<original_name>"`
  - `X-Evidence-SHA256: <sha256_hex>`
  - `X-Content-Type-Options: nosniff`
- **Errors:** `404 Not Found`, `409 Conflict` (Disk checksum mismatch - flags evidence).

### 6.4 `PUT /api/evidence/{evidence_id}/verify`
- **Description:** Formally marks evidence as `Verified` or `Flagged`.
- **RBAC:** `Admin` or `Auditor`.
- **Response:** `200 OK` (`EvidenceOut`).

### 6.5 `PUT /api/evidence/{evidence_id}`
- **Description:** Updates evidence linkage or tag.
- **RBAC:** `Admin` or `Auditor`.
- **Validation Rule:** Blocked with `400 Bad Request` if `Company.sha_lock_enabled == true` and evidence is already `Verified`.
- **Response:** `200 OK` (`EvidenceOut`).

### 6.6 `GET /api/evidence/{evidence_id}/history`
- **Description:** Retrieves immutable audit trail of operations on this evidence.
- **Response:** `200 OK` (`list[AuditHistoryOut]`).
